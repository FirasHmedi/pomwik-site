For teams with a React Native app on Realm®

Your app still runs on Realm. Let's keep it shipping.

MongoDB deprecated Realm in September 2024 and ended support on 30 September 2025. Since then, users have reported build failures on newer React Native and Xcode versions. We help you keep your app building, then move your local data to SQLite. Our converter checks every object on copies of your files.

Three ways we can help

Know your risk

A short fixed-price diagnostic: what is likely to break next, and the cheapest way out (keep, patch or migrate).

Keep your app building

afterdb is an independent open-source fork of the realm-js SDK (v20) that we maintain (see its maintenance policy). It builds and runs on Android emulators (React Native 0.86 to 0.88, Expo SDK 56 to 58) and on the iPhone simulator (React Native 0.86 to 0.88 with Xcode 26.6, React Native 0.88.1 with Xcode 26.4.1), with nothing downloaded at install. Your code keeps import Realm from "realm".

Move to SQLite

We plan and build the move with you. Our open-source converter runs on a computer and checks every object, on copies of your .realm files, encrypted ones included.

Use afterdb in your app

Change two lines in package.json, then reinstall and rebuild (pod install on iOS):

"realm": "npm:@pomwik/afterdb@20.3.0",
"@realm/react": "npm:@pomwik/afterdb-react@0.20.1"

Code on GitHub (Apache-2.0). Packages on npm: @pomwik/afterdb and @pomwik/afterdb-react.

What is tested so far

The fork, on Android

  • React Native 0.88.1, new architecture: release build for all 4 Android ABIs
  • Runs on Android 7, 11 and 16 emulators, and Android 16 with 16 KB pages: read, write, live queries, encrypted realm, data kept after a restart
  • Also runs with React Native 0.86.3 and 0.87.1, and Expo SDK 56, 57 and 58 (emulator with 16 KB pages)
  • Release builds with R8 turned on work (the Expo SDK 58 default)
  • All 64-bit native libraries of our test app are 16 KB aligned (24 of 24)
  • OpenSSL 3.5.9 LTS included: nothing is downloaded at install or build time

The fork, on iOS

  • React Native 0.88.1: Debug and Release builds with Xcode 26.6 (with and without frameworks) and Xcode 26.4.1 (without frameworks)
  • New apps from the React Native 0.86.3 and 0.87.1 templates, Xcode 26.6, dynamic and static frameworks: Release build (CI run)
  • Runs on the iPhone simulator and keeps its data after a restart
  • The build for iPhone devices succeeds (without code signing)

The fork, in Node

  • Installs offline
  • Passes realm-js's own Node integration tests, with the same results as realm 20.2.0. Its Node engine binary is upstream's, unchanged.

Not tested yet

  • Real phones: so far only emulators and the iPhone simulator
  • iOS with Expo
  • Opening, after an app update on a phone, a file that realm 20.2.0 wrote (tested in Node only)
  • The package as published on npm. CI tests the packages it builds from the same commit. The Android OpenSSL files in the npm package were built outside CI and have not run there (details)

Details and logs: the compatibility matrix on GitHub.

The conversion tool

  1. Every object checked

    A SHA-256 hash per object and per table, foreign keys and a field-by-field sample. On our test file covering every supported type: zero differences.

  2. Values SQLite would lose

    NaN, -0, dates before 1970 and non-ASCII text are kept and checked. SQLite alone turns NaN into NULL and -0 into 0, without any warning.

  3. Queries compared one by one

    252 handwritten Realm queries run on both sides: 2 differences, both known and explained. Realm has quirks a naive port silently changes, like [c] folding only ASCII and Latin-1 letters.

The converter runs under Node 22 or later. It reads a private copy of your file, read-only, and never writes to the original. It refuses files that need a format upgrade, which older realm versions wrote. Details: the converter README.

Questions

It still works. Why act now?

It works until the next upgrade. The check looks at your versions and tells you which React Native, Xcode or Google Play change is likely to break your app.

We plan to move to a sync service.

If you need sync, that can be the right choice. Your local data and query behavior still have to move: we can plan and build that part with you. We compare the options in Leaving Realm in 2026.

What is not covered?

Device Sync, the old React Native architecture, bugs inside the Realm engine itself (we use the upstream engine unchanged), and Realm Swift, Kotlin and Flutter. SwiftPM is not supported yet. We say so before any work starts.

What about our users' data?

In a shipped app, the migration runs inside your app, on your users' phones. We plan and write that part with you. We check the conversion on copies of your files with our desktop tool, which never writes to your file. For the free check, we only need your versions and the error.
