What breaks today

  • iOS linking on React Native 0.86 and later;
  • builds with Xcode 26.4 (is_pod error);
  • npm ci hanging on install-time downloads;
  • Google Play's 16 KB rule for Realm 10, 11 and early 12, from 1 February 2027;
  • SwiftPM, the default in React Native 0.89.

Three ways we can help

Know your risk

A short fixed-price diagnostic: what breaks next, when, and the cheapest way out (keep, patch or migrate).

Keep your app building

We are finishing an independent, open-source fork of the realm-js SDK (v20) that fixes these breakages, with nothing downloaded at install. Your code keeps import Realm from "realm".

Leave Realm safely

Your .realm files converted to SQLite on the device, encrypted files included, with checksums and a way back. Every query is compared before and after.

What our conversion tool already does

  1. Every object checked

    A SHA-256 hash per object and per table, foreign keys and a field-by-field sample. On our test file covering every supported type: zero differences.

  2. Values SQLite would lose

    NaN, -0, dates before 1970 and non-ASCII text are kept and checked. A plain copy changes some of them without any warning.

  3. Queries compared one by one

    196 Realm queries run on both sides: 2 differences, both known and explained. Realm has quirks a naive port silently changes, like [c] folding only Latin-1.

Questions

It still works. Why act now?

It works until the next upgrade. The check tells you which React Native, Xcode or Google Play change will break your app, and when.

We plan to move to a sync service.

If you need sync, that can be the right choice. Your local data and query behaviour still have to move with you: we can handle that part.

What is not covered?

Device Sync, the old React Native architecture, and bugs inside the Realm engine itself. We say so before any work starts.

What about our users' data?

We work on test data or inside your infrastructure. Your users' data never leaves your systems.
