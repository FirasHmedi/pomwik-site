@realm/react pulls a second react-native: Failed to apply plugin 'com.facebook.react.rootproject'

@realm/react installe un deuxième react-native : Failed to apply plugin 'com.facebook.react.rootproject'

Your Android build fails while Gradle configures the project. @realm/react 0.20.0 can pull in its own copy of react-native, and the build picks the wrong one.

Votre build Android échoue pendant que Gradle configure le projet. @realm/react 0.20.0 peut installer sa propre copie de react-native, et le build prend la mauvaise.

Updated 9 November 2026.

Mis à jour le 9 novembre 2026.

The error

L'erreur

* What went wrong:
A problem occurred evaluating root project '…'.
> Failed to apply plugin 'com.facebook.react.rootproject'.
   > A problem occurred configuring project ':app'.
      > Failed to notify project evaluation listener.
         > /…/node_modules/react-native/sdks/hermes-engine/version.properties (No such file or directory)

yarn why react-native shows a second copy under @realm/react:

yarn why react-native montre une deuxième copie sous @realm/react :

@realm/react@npm:0.20.0 └─ react-native@npm:0.82.0 (via npm:>=0.68)

When it happens

Quand ça arrive

  • @realm/react 0.20.0, the last release (17 October 2025), in an Android build.
  • @realm/react 0.20.0, la dernière version (17 octobre 2025), dans un build Android.
  • Reported in #7066 (18 October 2025) with React Native 0.81.4, realm 20.2.0 and Yarn 3.6.4. Another user reported the same.
  • Signalé dans #7066 (18 octobre 2025) avec React Native 0.81.4, realm 20.2.0 et Yarn 3.6.4. Un autre utilisateur a signalé la même chose.

Why

Pourquoi

@realm/react 0.20.0 lists react-native (>=0.68) in its optionalDependencies. Your package manager may then install another react-native version in node_modules/@realm/react/node_modules, and React Native's Gradle plugin uses the wrong copy.

@realm/react 0.20.0 liste react-native (>=0.68) dans ses optionalDependencies. Votre gestionnaire de paquets peut alors installer une autre version de react-native dans node_modules/@realm/react/node_modules, et le plugin Gradle de React Native utilise la mauvaise copie.

Fix with afterdb

Corriger avec afterdb

@pomwik/afterdb-react declares react-native as an optional peer dependency instead, so it never installs its own copy.

@pomwik/afterdb-react déclare plutôt react-native comme dépendance pair optionnelle, donc il n'installe jamais sa propre copie.

In package.json, point the two Realm packages to afterdb:

Dans package.json, faites pointer les deux paquets Realm vers afterdb :

"realm": "npm:@pomwik/afterdb@20.3.1",
"@realm/react": "npm:@pomwik/afterdb-react@0.20.2"

Then reinstall, run pod install on iOS, and rebuild. For Expo dev builds, run npx expo prebuild --clean. Your code keeps import Realm from "realm". If you do not use @realm/react, the first line is enough.

Puis réinstallez, lancez pod install sur iOS, et recompilez. Pour les dev builds Expo, lancez npx expo prebuild --clean. Votre code garde import Realm from "realm". Si vous n'utilisez pas @realm/react, la première ligne suffit.

afterdb is an independent open-source fork of the realm-js SDK v20 (Apache-2.0) that we maintain (see its maintenance policy), for apps on realm 20.x without Device Sync. It is not an official Realm release. Code on GitHub, package on npm.

afterdb est un fork open source indépendant du SDK realm-js v20 (Apache-2.0), que nous maintenons (voir sa politique de maintenance), pour les apps sur realm 20.x sans Device Sync. Ce n'est pas une version officielle de Realm. Code sur GitHub, paquet sur npm.

You can check the change with npm view @pomwik/afterdb-react peerDependenciesMeta. The Yarn 3.6.4 setup from #7066 is not in our test matrix.

Vous pouvez vérifier le changement avec npm view @pomwik/afterdb-react peerDependenciesMeta. La configuration Yarn 3.6.4 de #7066 n'est pas dans notre matrice de tests.

Without afterdb

Sans afterdb

  • Pin react-native to your app's version. With Yarn, in package.json: 
    "resolutions": {
  "react-native": "your react-native version"
}
    The author of #7066 posted this and confirmed it works.
  • Fixez react-native à la version de votre app. Avec Yarn, dans package.json : 
    "resolutions": {
  "react-native": "votre version de react-native"
}
    L'auteur de #7066 a publié cette solution et confirmé qu'elle marche.
  • With npm, the same idea uses overrides. We have not tested it.
  • Avec npm, la même idée passe par overrides. On ne l'a pas testé.
  • yarn dedupe did not help the author.
  • yarn dedupe n'a pas aidé l'auteur.
