Realm on Xcode 26.4: 'is_pod' cannot be specialized

Realm sous Xcode 26.4 : 'is_pod' cannot be specialized

Your React Native app uses realm 20.2.0 and the iOS build fails after an update to Xcode 26.4. The cause is one header shipped inside the realm package. It was fixed for the Realm engine and for Realm Swift in February 2026, but no realm-js release has the fix.

Votre app React Native utilise realm 20.2.0 et le build iOS échoue après une mise à jour vers Xcode 26.4. La cause est un en-tête livré dans le paquet realm. Il a été corrigé pour le moteur Realm et pour Realm Swift en février 2026, mais aucune version de realm-js n'a la correction.

Updated 10 November 2026.

Mis à jour le 10 novembre 2026.

The error

L'erreur

'is_pod' cannot be specialized: Users are not allowed to specialize this standard library entity

Xcode shows it on lines like these, expanded from macros in external/s2/base/macros.h:

Xcode l'affiche sur des lignes comme celles-ci, issues des macros de external/s2/base/macros.h :

DECLARE_POD(S1Angle);
PROPAGATE_POD_FROM_TEMPLATE_ARGUMENT(Vector2);
PROPAGATE_POD_FROM_TEMPLATE_ARGUMENT(Vector3);

When it happens

Quand ça arrive

  • iOS builds with realm 20.2.0, the last realm-js release (11 August 2025).
  • Builds iOS avec realm 20.2.0, la dernière version de realm-js (11 août 2025).
  • Xcode 26.4. Reported in #7115 (31 March 2026) with React Native 0.77.3. Realm Swift users saw the same error in realm-swift #8812.
  • Xcode 26.4. Signalé dans #7115 (31 mars 2026) avec React Native 0.77.3. Des utilisateurs de Realm Swift ont eu la même erreur dans realm-swift #8812.
  • The header ships only in the Apple part of the realm package. Android builds do not include it.
  • L'en-tête n'est livré que dans la partie Apple du paquet realm. Les builds Android ne l'incluent pas.
  • Later Xcode versions may not hit it: a public iOS release build with unpatched realm 20.2.0 succeeds on Xcode 26.6 (BlueWallet CI, 9 November 2026). We have not tested unpatched realm on Xcode 26.6 ourselves.
  • Les versions suivantes de Xcode ne le rencontrent peut-être pas : un build release iOS public avec realm 20.2.0 non corrigé réussit sous Xcode 26.6 (CI de BlueWallet, 9 novembre 2026). On n'a pas testé nous-mêmes realm non corrigé sous Xcode 26.6.

Why

Pourquoi

realm 20.2.0 ships a prebuilt engine, realm-core.xcframework. One of its headers comes from the s2 geometry library and specializes std::is_pod. The C++ standard library in Xcode 26.4 forbids that, so the compiler stops.

realm 20.2.0 livre un moteur précompilé, realm-core.xcframework. Un de ses en-têtes vient de la bibliothèque de géométrie s2 et spécialise std::is_pod. La bibliothèque standard C++ de Xcode 26.4 l'interdit, donc le compilateur s'arrête.

The engine fix is realm-core commit d8f21f9 (22 February 2026), and Realm Swift 20.0.4 includes it. realm-js was never updated: its last release is still 20.2.0.

La correction du moteur est le commit realm-core d8f21f9 (22 février 2026), et Realm Swift 20.0.4 l'inclut. realm-js n'a jamais été mis à jour : sa dernière version reste la 20.2.0.

Fix with afterdb

Corriger avec afterdb

afterdb ships the same header with the realm-core fix applied.

afterdb livre le même en-tête avec la correction de realm-core appliquée.

In package.json, point the two Realm packages to afterdb:

Dans package.json, faites pointer les deux paquets Realm vers afterdb :

"realm": "npm:@pomwik/afterdb@20.3.1",
"@realm/react": "npm:@pomwik/afterdb-react@0.20.2"

Then reinstall, run pod install on iOS, and rebuild. For Expo dev builds, run npx expo prebuild --clean. Your code keeps import Realm from "realm". If you do not use @realm/react, the first line is enough.

Puis réinstallez, lancez pod install sur iOS, et recompilez. Pour les dev builds Expo, lancez npx expo prebuild --clean. Votre code garde import Realm from "realm". Si vous n'utilisez pas @realm/react, la première ligne suffit.

afterdb is an independent open-source fork of the realm-js SDK v20 (Apache-2.0) that we maintain (see its maintenance policy), for apps on realm 20.x without Device Sync. It is not an official Realm release. Code on GitHub, package on npm.

afterdb est un fork open source indépendant du SDK realm-js v20 (Apache-2.0), que nous maintenons (voir sa politique de maintenance), pour les apps sur realm 20.x sans Device Sync. Ce n'est pas une version officielle de Realm. Code sur GitHub, paquet sur npm.

We build and run it in CI with React Native 0.88.1. On Xcode 26.4.1 without frameworks, the app starts on the iPhone simulator and keeps its data after a restart. On Xcode 26.6, with no frameworks, static frameworks and dynamic frameworks, the app starts on the simulator. On both, the build for iPhone devices succeeds. With new apps from the React Native 0.86.3 and 0.87.1 templates on Xcode 26.6, with dynamic and static frameworks, the app runs on the simulator, keeps its data after a restart, and the device build succeeds (CI run). Not tested yet: real iPhones, React Native 0.86 or 0.87 on Xcode 26.4, Expo on iOS, and React Native 0.77.

On le compile et on le lance en CI avec React Native 0.88.1. Sous Xcode 26.4.1 sans frameworks, l'app démarre sur le simulateur iPhone et garde ses données après redémarrage. Sous Xcode 26.6, sans frameworks, avec frameworks statiques et dynamiques, l'app démarre sur le simulateur. Dans les deux cas, le build pour appareil iPhone réussit. Avec de nouvelles apps créées depuis les modèles React Native 0.86.3 et 0.87.1 sous Xcode 26.6, avec frameworks dynamiques et statiques, l'app tourne sur le simulateur, garde ses données après redémarrage, et le build pour appareil réussit (exécution CI). Pas encore testé : de vrais iPhone, React Native 0.86 ou 0.87 sous Xcode 26.4, Expo sur iOS, et React Native 0.77.

Without afterdb

Sans afterdb

  • Patch the header yourself. In each slice of node_modules/realm/prebuilds/apple/realm-core.xcframework, edit Headers/external/s2/base/macros.h so that the DECLARE_POD and PROPAGATE_POD_FROM_TEMPLATE_ARGUMENT macros expand to nothing, as realm-core commit d8f21f9 does. Keep the change with patch-package. This is what afterdb does. We did not find a public patch for realm-js.
  • Corrigez l'en-tête vous-même. Dans chaque tranche de node_modules/realm/prebuilds/apple/realm-core.xcframework, modifiez Headers/external/s2/base/macros.h pour que les macros DECLARE_POD et PROPAGATE_POD_FROM_TEMPLATE_ARGUMENT ne produisent rien, comme le fait le commit realm-core d8f21f9. Gardez le changement avec patch-package. C'est ce que fait afterdb. On n'a pas trouvé de correctif public pour realm-js.
  • Build with Xcode 26.3 or earlier. App Store Connect has required Xcode 26 since 28 April 2026, so 26.3 is still accepted, but you stay on an old Xcode until the header is fixed.
  • Compilez avec Xcode 26.3 ou plus ancien. App Store Connect exige Xcode 26 depuis le 28 avril 2026, donc la 26.3 est encore acceptée, mais vous restez sur un ancien Xcode tant que l'en-tête n'est pas corrigé.
  • Move to Xcode 26.6. It may avoid the error: the BlueWallet release build cited above uses unpatched realm 20.2.0 on Xcode 26.6 and succeeds. We have not tested this ourselves.
  • Passez à Xcode 26.6. Ça évite peut-être l'erreur : le build release de BlueWallet cité plus haut utilise realm 20.2.0 non corrigé sous Xcode 26.6 et réussit. On ne l'a pas testé nous-mêmes.
