Realm release builds with R8 crash at start: SSLHelper

Builds release Realm avec R8 qui plantent au démarrage : SSLHelper

Debug works. The release build of your Android app crashes as soon as it opens. If you use Realm and R8 is on, the cause can be one class that R8 removed.

Le debug marche. Le build release de votre app Android plante dès l'ouverture. Si vous utilisez Realm et que R8 est activé, la cause peut être une classe que R8 a supprimée.

Updated 9 November 2026.

Mis à jour le 9 novembre 2026.

The error

L'erreur

In logcat, look for:

Dans logcat, cherchez :

ClassNotFoundException: io.realm.react.util.SSLHelper

Older reports show the same class in other errors, for example #2658 (2019):

Des signalements plus anciens montrent la même classe dans d'autres erreurs, par exemple #2658 (2019) :

java.lang.UnsatisfiedLinkError: couldn't find DSO to load: librealmreact.so caused by: Didn't find class "io.realm.react.util.SSLHelper" on path: DexPathList

When it happens

Quand ça arrive

  • Android release builds with R8 on (minifyEnabled, or enableProguardInReleaseBuilds in React Native apps) and no keep rule for Realm.
  • Builds release Android avec R8 activé (minifyEnabled, ou enableProguardInReleaseBuilds dans les apps React Native) et sans règle keep pour Realm.
  • Expo SDK 58 turns R8 on by default in release builds (Expo's SDK 58 upgrade guide, 21 October 2026). An app that moves to Expo SDK 58 can crash in production while debug builds work.
  • Expo SDK 58 active R8 par défaut dans les builds release (guide de passage à SDK 58 d'Expo, 21 octobre 2026). Une app qui passe à Expo SDK 58 peut planter en production alors que les builds debug marchent.
  • We hit it on 6 November 2026 while testing afterdb with Expo SDK 58. Realm users reported it before, in #2658 and #6074.
  • On l'a rencontré le 6 novembre 2026 en testant afterdb avec Expo SDK 58. Des utilisateurs de Realm l'avaient déjà signalé, dans #2658 et #6074.

Why

Pourquoi

Realm's native code looks up io.realm.react.util.SSLHelper by name when it loads (FindClass in JNI_OnLoad). No Java code uses that class, and the realm Android library ships no keep rule. R8 sees an unused class and removes it, and the app crashes at start.

Le code natif de Realm cherche io.realm.react.util.SSLHelper par son nom au chargement (FindClass dans JNI_OnLoad). Aucun code Java n'utilise cette classe, et la bibliothèque Android de realm ne livre aucune règle keep. R8 voit une classe inutilisée et la supprime, et l'app plante au démarrage.

Fix with afterdb

Corriger avec afterdb

afterdb ships the keep rule in the package (consumer-rules.pro), so you add nothing to your app.

afterdb livre la règle keep dans le paquet (consumer-rules.pro), donc vous n'ajoutez rien à votre app.

In package.json, point the two Realm packages to afterdb:

Dans package.json, faites pointer les deux paquets Realm vers afterdb :

"realm": "npm:@pomwik/afterdb@20.3.1",
"@realm/react": "npm:@pomwik/afterdb-react@0.20.2"

Then reinstall, run pod install on iOS, and rebuild. For Expo dev builds, run npx expo prebuild --clean. Your code keeps import Realm from "realm". If you do not use @realm/react, the first line is enough.

Puis réinstallez, lancez pod install sur iOS, et recompilez. Pour les dev builds Expo, lancez npx expo prebuild --clean. Votre code garde import Realm from "realm". Si vous n'utilisez pas @realm/react, la première ligne suffit.

afterdb is an independent open-source fork of the realm-js SDK v20 (Apache-2.0) that we maintain (see its maintenance policy), for apps on realm 20.x without Device Sync. It is not an official Realm release. Code on GitHub, package on npm.

afterdb est un fork open source indépendant du SDK realm-js v20 (Apache-2.0), que nous maintenons (voir sa politique de maintenance), pour les apps sur realm 20.x sans Device Sync. Ce n'est pas une version officielle de Realm. Code sur GitHub, paquet sur npm.

Tested locally: release builds with R8 on, for our bare React Native example and for Expo SDK 58 with no rule in the app. The app runs on Android emulators. Not tested yet: real devices.

Testé en local : builds release avec R8 activé, pour notre exemple React Native sans Expo et pour Expo SDK 58, sans règle dans l'app. L'app tourne sur émulateurs Android. Pas encore testé : vrais appareils.

Without afterdb

Sans afterdb

Add this line to android/app/proguard-rules.pro:

Ajoutez cette ligne à android/app/proguard-rules.pro :

-keep class io.realm.react.** { *; }

A Realm maintainer suggested a keep rule for io.realm.react.** in #6074 (2023), and three users confirmed it worked. With Expo, the android folder is generated, so add the rule through the android.extraProguardRules option of expo-build-properties, or a config plugin. We have not tested the Expo route.

Un mainteneur de Realm a proposé une règle keep pour io.realm.react.** dans #6074 (2023), et trois utilisateurs ont confirmé qu'elle marchait. Avec Expo, le dossier android est généré, donc ajoutez la règle via l'option android.extraProguardRules d'expo-build-properties, ou un config plugin. On n'a pas testé la voie Expo.
