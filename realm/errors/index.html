Realm® build errors in 2026 and how to fix them

Erreurs de build Realm® en 2026 et comment les corriger

The last realm-js release is 20.2.0, from August 2025. Since then, new React Native, Xcode, Expo and Google Play versions have broken builds that used to work. Each page below gives the exact error, the cause, a manual workaround when there is one, and what afterdb changes.

La dernière version de realm-js est la 20.2.0, d'août 2025. Depuis, de nouvelles versions de React Native, Xcode, Expo et Google Play ont cassé des builds qui marchaient. Chaque page ci-dessous (en anglais) donne l'erreur exacte, la cause, un contournement manuel quand il existe, et ce que change afterdb.

Updated 11 November 2026.

The fix with afterdb

La solution avec afterdb

afterdb is an independent open-source fork of the realm-js SDK v20 (Apache-2.0) that we maintain (see its maintenance policy). It fixes the build and install errors above for apps on realm 20.x without Device Sync, except the 16 KB warning, whose cause is not known. For 16 KB pages, every 64-bit native library in our test app passes the 16 KB checks. It is not an official Realm release.

afterdb est un fork open source indépendant du SDK realm-js v20 (Apache-2.0), que nous maintenons (voir sa politique de maintenance). Il corrige les erreurs de build et d'installation ci-dessus pour les apps sur realm 20.x sans Device Sync, sauf l'avertissement 16 Ko, dont la cause n'est pas connue. Pour les pages de 16 Ko, toutes les bibliothèques natives 64 bits de notre app de test passent les contrôles. Ce n'est pas une version officielle de Realm.

"realm": "npm:@pomwik/afterdb@20.3.1",
"@realm/react": "npm:@pomwik/afterdb-react@0.20.2"

Then reinstall, run pod install on iOS, and rebuild. For Expo dev builds, run npx expo prebuild --clean. Your code keeps import Realm from "realm".

Puis réinstallez, lancez pod install sur iOS, et recompilez. Pour les dev builds Expo, lancez npx expo prebuild --clean. Votre code garde import Realm from "realm".

Tested with React Native 0.88.1 on Android 7, 11 and 16 emulators and on Android 16 with 16 KB pages; with React Native 0.86.3 and 0.87.1 and Expo SDK 56, 57 and 58 on the 16 KB emulator; and on the iPhone simulator with React Native 0.88.1 on Xcode 26.4.1 and 26.6, and with new apps from the React Native 0.86.3 and 0.87.1 templates on Xcode 26.6 with dynamic and static frameworks (CI run).

Testé avec React Native 0.88.1 sur émulateurs Android 7, 11 et 16 et sur Android 16 avec pages de 16 Ko ; avec React Native 0.86.3 et 0.87.1 et Expo SDK 56, 57 et 58 sur l'émulateur 16 Ko ; et sur le simulateur iPhone avec React Native 0.88.1 sous Xcode 26.4.1 et 26.6, et avec de nouvelles apps créées depuis les modèles React Native 0.86.3 et 0.87.1 sous Xcode 26.6, frameworks dynamiques et statiques (exécution CI).

In CI, a test app on realm 20.2.0 switches to afterdb and back, with a plain and an encrypted file: afterdb checks every object realm 20.2.0 wrote, and realm 20.2.0 reads what afterdb wrote. This passes with Release builds on Android 16 and Android 11 emulators and on the iPhone simulator (CI run). The package as published on npm installs and runs in a new React Native 0.88.1 app, on an Android 16 emulator and on the iPhone simulator (CI run).

En CI, une app de test sur realm 20.2.0 passe à afterdb puis revient, avec un fichier normal et un fichier chiffré : afterdb vérifie chaque objet écrit par realm 20.2.0, et realm 20.2.0 relit ce qu'afterdb a écrit. Ça réussit avec des builds Release sur émulateurs Android 16 et Android 11 et sur le simulateur iPhone (exécution CI). Le paquet publié sur npm s'installe et tourne dans une nouvelle app React Native 0.88.1, sur un émulateur Android 16 et sur le simulateur iPhone (exécution CI).

Not tested yet: real devices, running the arm64-v8a build in CI, the armeabi-v7a build on an ARM processor (it ran only through ARM translation), Expo on iOS, the switch with Debug builds, and switching from a realm version other than 20.2.0, such as realm 10, 11 or 12. Details: the compatibility matrix on GitHub.

Pas encore testé : vrais appareils, le build arm64-v8a en CI, le build armeabi-v7a sur un vrai processeur ARM (il n'a tourné que via la traduction ARM), Expo sur iOS, le passage avec des builds Debug, et le passage depuis une autre version que realm 20.2.0, comme realm 10, 11 ou 12. Détails : la matrice de compatibilité sur GitHub.

Not fixed by afterdb

Ce qu'afterdb ne corrige pas

  • Debug builds on React Native 0.83 and later can throw Accessing object which has been invalidated or deleted. It comes from React (react/react #35126), and release builds are not affected. Workarounds are listed in the afterdb README. See also #7086.
  • Les builds Debug à partir de React Native 0.83 peuvent lever Accessing object which has been invalidated or deleted. Ça vient de React (react/react #35126), et les builds release ne sont pas touchés. Les contournements sont listés dans le README d'afterdb. Voir aussi #7086.
  • Bugs inside the Realm engine itself: afterdb uses the upstream engine unchanged.
  • Les bugs du moteur Realm lui-même : afterdb utilise le moteur d'origine inchangé.
  • Device Sync and the old React Native architecture.
  • Device Sync et l'ancienne architecture de React Native.
