Realm on React Native 0.86+: iOS Undefined symbols for jsi::Value

Realm sur React Native 0.86+ : Undefined symbols iOS pour jsi::Value

After an upgrade to React Native 0.86 or later, the iOS build of an app on realm 20.2.0 stops at the link step. It was reported with pods built as dynamic frameworks.

Après une mise à jour vers React Native 0.86 ou plus, le build iOS d'une app sur realm 20.2.0 s'arrête à l'édition de liens. Le problème a été signalé avec des pods compilés en frameworks dynamiques.

Updated 11 November 2026.

Mis à jour le 11 novembre 2026.

The error

L'erreur

Undefined symbols for architecture x86_64:
  "facebook::jsi::Value::asBool() const", referenced from: ...
  "facebook::jsi::Value::asObject(facebook::jsi::IRuntime&) const &", referenced from: ...
  "facebook::react::TurboModule::TurboModule(...)", referenced from: ...

From the description of realm-js pull request #7157. The architecture in the first line depends on what you build.

Tiré de la description de la pull request realm-js #7157. L'architecture de la première ligne dépend de ce que vous compilez.

When it happens

Quand ça arrive

  • realm 20.2.0 on iOS with React Native 0.86 or later, new architecture.
  • realm 20.2.0 sur iOS avec React Native 0.86 ou plus, nouvelle architecture.
  • Pods built as frameworks: use_frameworks! in the Podfile, often needed for Firebase. The pull request author used use_frameworks! :linkage => :dynamic with React Native 0.87.1, and verified the fix with that setup only.
  • Pods compilés en frameworks : use_frameworks! dans le Podfile, souvent nécessaire pour Firebase. L'auteur de la pull request utilisait use_frameworks! :linkage => :dynamic avec React Native 0.87.1, et n'a vérifié la correction qu'avec cette configuration.

Why

Pourquoi

realm's RealmJS.podspec only declares s.dependency 'React'. According to the pull request, when pods are built as frameworks, React Native 0.86 and later no longer link hermes-engine, React-jsi and ReactCommon/turbomodule/core into the RealmJS target through that line, so the linker cannot find the JSI symbols.

Le RealmJS.podspec de realm déclare seulement s.dependency 'React'. D'après la pull request, quand les pods sont compilés en frameworks, React Native 0.86 et plus ne lient plus hermes-engine, React-jsi et ReactCommon/turbomodule/core à la cible RealmJS via cette ligne, donc l'éditeur de liens ne trouve pas les symboles JSI.

A fix was proposed upstream in #7157 on 25 September 2026 by TPXP. It has no review and is not merged.

Une correction a été proposée en amont dans #7157 le 25 septembre 2026 par TPXP. Elle n'a pas de relecture et n'est pas fusionnée.

Fix with afterdb

Corriger avec afterdb

afterdb includes the fix from #7157, credited to its author, plus one more change to the header search paths that the fix needed in our builds.

afterdb inclut la correction de #7157, créditée à son auteur, plus un changement des chemins de recherche des en-têtes dont la correction avait besoin dans nos builds.

In package.json, point the two Realm packages to afterdb:

Dans package.json, faites pointer les deux paquets Realm vers afterdb :

"realm": "npm:@pomwik/afterdb@20.3.1",
"@realm/react": "npm:@pomwik/afterdb-react@0.20.2"

Then reinstall, run pod install on iOS, and rebuild. For Expo dev builds, run npx expo prebuild --clean. Your code keeps import Realm from "realm". If you do not use @realm/react, the first line is enough.

Puis réinstallez, lancez pod install sur iOS, et recompilez. Pour les dev builds Expo, lancez npx expo prebuild --clean. Votre code garde import Realm from "realm". Si vous n'utilisez pas @realm/react, la première ligne suffit.

afterdb is an independent open-source fork of the realm-js SDK v20 (Apache-2.0) that we maintain (see its maintenance policy), for apps on realm 20.x without Device Sync. It is not an official Realm release. Code on GitHub, package on npm.

afterdb est un fork open source indépendant du SDK realm-js v20 (Apache-2.0), que nous maintenons (voir sa politique de maintenance), pour les apps sur realm 20.x sans Device Sync. Ce n'est pas une version officielle de Realm. Code sur GitHub, paquet sur npm.

We build and run it in CI with new apps from the React Native 0.86.3 and 0.87.1 templates, on Xcode 26.6 with dynamic and static frameworks. React Native 0.87.1 with dynamic frameworks is the setup of the pull request author. The Release build succeeds, the app runs on the iPhone simulator and keeps its data after a restart, and the build for iPhone devices succeeds. With dynamic frameworks, RealmJS.framework is embedded in the app (CI run).

On le compile et on le lance en CI avec de nouvelles apps créées depuis les modèles React Native 0.86.3 et 0.87.1, sous Xcode 26.6 avec frameworks dynamiques et statiques. React Native 0.87.1 avec frameworks dynamiques est la configuration de l'auteur de la pull request. Le build Release réussit, l'app tourne sur le simulateur iPhone et garde ses données après redémarrage, et le build pour appareil iPhone réussit. Avec les frameworks dynamiques, RealmJS.framework est intégré à l'app (exécution CI).

We also build and run it with React Native 0.88.1 on Xcode 26.6 with no frameworks, static frameworks and dynamic frameworks, and on Xcode 26.4.1 without frameworks: the app starts on the iPhone simulator and the build for iPhone devices succeeds. Not tested yet: Expo on iOS, real iPhones, Debug builds of the React Native 0.86.3 and 0.87.1 apps, and React Native built from source (our iOS builds in CI use React Native's prebuilt core, the default).

On le compile et on le lance aussi avec React Native 0.88.1 sous Xcode 26.6 sans frameworks, avec frameworks statiques et dynamiques, et sous Xcode 26.4.1 sans frameworks : l'app démarre sur le simulateur iPhone et le build pour appareil iPhone réussit. Pas encore testé : Expo sur iOS, de vrais iPhone, les builds Debug des apps React Native 0.86.3 et 0.87.1, et React Native compilé depuis les sources (nos builds iOS en CI utilisent le cœur précompilé de React Native, le réglage par défaut).

Without afterdb

Sans afterdb

  • Apply the change from #7157 with patch-package: in RealmJS.podspec, replace s.dependency 'React' with install_modules_dependencies(s). The author reports it works in their app. In afterdb we also had to turn HEADER_SEARCH_PATHS from an array into a string, because install_modules_dependencies appends to it. Check that your build still finds every header.
  • Appliquez le changement de #7157 avec patch-package : dans RealmJS.podspec, remplacez s.dependency 'React' par install_modules_dependencies(s). L'auteur dit que ça marche dans son app. Dans afterdb, on a aussi dû transformer HEADER_SEARCH_PATHS de tableau en chaîne, car install_modules_dependencies y ajoute des valeurs. Vérifiez que votre build trouve encore tous les en-têtes.
  • The pull request describes the error only with frameworks. If your app can build its pods without use_frameworks!, that should avoid it. We have not tested this.
  • La pull request ne décrit l'erreur qu'avec des frameworks. Si votre app peut compiler ses pods sans use_frameworks!, ça devrait l'éviter. On ne l'a pas testé.
